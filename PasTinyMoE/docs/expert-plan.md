## Routing the catalog

The ten categories are a menu and metadata grouping first. They do not require ten more neural models.

1. Preserve manual expert selection. For the three- and five-expert editions, route directly among the available experts.
2. For SD100, let the user choose a category or supply a short explicit prefix. A compact global rule index can suggest a category when none is selected, with fallback for ties.
3. Route within the selected category using question vocabulary and evaluated paraphrase rules. A global lookup still needs only one compact index and a bounded score array.
4. Treat category and selected expert as application state. Do not repeatedly consume the tiny model's context with a long catalog or verbose system prompt.
5. Keep role-play experts explicitly selected by the user/game. A mention of a spaceship should not silently turn a factual astronomy answer into fiction.
6. Use ambiguous terms as router tests: memory can mean DOS memory or human memory; string can mean Pascal data or an ordinary word. Ask for category selection when context cannot resolve the distinction.
7. Unknown topics are a real result. Show the catalog or fall back to the selected general entry point only when its documented syllabus covers the question.

The host owns game inventory, locations, events, and persistent conversation state. Character experts supply short language conditioned on a compact input; they do not decide authoritative game facts. They have no automatic memory of prior requests.

## Work that should remain ordinary Pascal code

Do not allocate neural models merely to replace reliable calculations or operating-system calls:

- Arithmetic, unit conversions, dates, sorting, random numbers, and dice.
- Current free memory, directory contents, disk capacity, and hardware detection.
- Command execution, source compilation, and exact game rules.

An expert may identify the intent, choose a formula/tool ID, or explain a returned result. The Pascal program performs the exact operation and supplies its real result. A current-state question must not be answered from a memorized example.

## Recommended build order

1. Prove the runtime and original model first.
2. Train/evaluate DOS Guide, Turbo Pascal Coach, and Pocket Naturalist using approved existing material.
3. Add PC Workbench and Word Bench as separately evaluated specialists; then test whether the five shared-core banks retain useful quality.
4. Expand the categories that actually show demand and reliable results. Word/fact-reference tasks can be tested against ordinary lookup tables; model size alone is not a benefit.
5. Keep the 100-entry catalog as the intended product map. Do not produce 100 files merely to meet a count, or call unexplored model scopes finished experts.

No training records or new specialist weights were generated while writing this catalog.
